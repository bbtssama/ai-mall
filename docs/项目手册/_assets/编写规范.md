# 项目手册 · 编写规范（子代理必读）

> 本文件是 `docs/项目手册/` 全部页面必须共同遵守的**协议**。
> 阅读顺序：本文件 → `_template.html`（骨架）→ `_assets/style.css` 的类名清单（用哪个类就查一下）。

---

## 一、这份手册是给谁看的

**读者画像**：初级 Java 后端求职者。这个项目他**部分自己写的、部分 AI 写的**；技术栈"大概知道"但**很不熟悉**；**即将拿它去面试**。

**他的终极目的**：**快速了解、理解这个项目的结构与功能**，并能在面试里讲出来。

**由此推出的两条铁律**：

1. **不是写教程，是写"带路的地图"。** 他已经有 3.8 万行 md 详解了，缺的不是知识，是**结构**——让他知道"这个项目由哪些块组成、每块干什么、互相怎么连、面试官问哪块"。
2. **每个技术点必须回答"为什么"。** 读者是"讲不出道理就没底气吹"的类型。只讲"我们用了 X"是废的；必须讲"为什么需要 X / 不用 X 会怎样 / 为什么不用 Y"。

## 二、口径红线（写错 = 面试翻车，最高优先级）

以下各条是项目已确立的**面试口径**，**任何页面不得违背**：

| # | 红线 | 正确说法 | 禁止说法 |
|---|---|---|---|
| 1 | **扣库存** | "行锁 + `WHERE stock>=?` 条件更新（CAS 思想）" | 绝不说"乐观锁"。`t_product_sku.version` 是**纯预留字段、从未参与比对** |
| 2 | **幂等设计** | "幂等设计（四种手段：唯一索引 / 状态机条件更新 / 一次性 token / 消费端回查）" | 绝不说"**幂等四式**"（这是自造名词，已废弃） |
| 3 | **RAG 边界** | "RAG 只答**非结构化**内容（商品说明书 + UGC 种草笔记）；**价格、库存走 SQL**" | 绝不说"RAG 什么都能答" |
| 4 | **AI 定位** | "AI 是**了解层**，重心在传统后端（事务/并发/缓存/消息）" | 不要把 AI 写成项目主打 |
| 5 | **超卖的数据依据** | "数据量是**触发条件的标尺**，不是选型的理由" | 绝不说"因为只有几百条数据所以不用 ES/不用分布式锁"（**规模借口**） |
| 6 | **服务化拆分** | "只拆了 **ai-service**，主体保持单体" | 不要写成"微服务架构" |
| 7 | **商品搜索** | "当前是 `LIKE` 模糊匹配，**还没做成熟搜索方案**" | 不要说"用 MySQL 全文索引搜商品"（全文索引用在**笔记**上） |

## 四、页面结构契约

**骨架必须照抄 `_template.html`**，只替换两处：
1. `<title>` / `data-page` / `.crumb` / `h1` / `.lede` / `.head-meta` 里的占位
2. `CONTENT:START` 与 `CONTENT:END` 之间的正文

**不要手写侧边栏、工具栏、页内目录、页脚导航**——`app.js` 会自动注入。

### 三层渐进式披露（本手册的灵魂，必须遵守）

每个技术点按这个顺序组织：

| 层 | 默认状态 | 写什么 | HTML |
|---|---|---|---|
| **第 1 层** | **可见** | 一句话是什么 + **为什么需要它**（业务理由）+ 一个具体比喻 | `<p>` + `.callout.analogy` |
| **第 2 层** | 折叠 | 机制图解 + **真实代码片段**（3~10 行，带 `文件:行号`） | `<details class="lvl mech">` |
| **第 3 层** | 折叠 | 面试怎么讲（30 秒版）+ ⚠️ 别说错 | `<details class="lvl talk">` |

**为什么这样设计**：同时服务"30 分钟速览"（只看第 1 层）和"面试冲刺"（展开第 2、3 层）。不要把所有内容都平铺——那会让页面变成第二份详解文档，失去价值。

### 可用组件速查

| 想要的效果 | 用这个 |
|---|---|
| 技术点卡片 | `<div class="card">` + `.card-title` + `.card-sub` |

| 折叠块 | `<details class="lvl mech">` / `.lvl talk` / `.lvl code` |

| 表格 | `.tbl-wrap` > `<table>` |

| 标签 | `<span class="tag">code</span>` |

### 硬性禁止

- **禁止 emoji**（用 CSS 徽章和 `.callout` 表达语气；项目已有的 `⚠️` 一律写成「注意」或放进 `.redline`）
- **禁止外部依赖**：不得引用任何 CDN、字体、图片、`<script src>` 外链（除 `_assets/app.js`）
- **禁止 `fetch` / XHR**（`file://` 下会被 CORS 拦截）
- **禁止臆造代码**：所有代码片段必须**先用 Read 工具读真实文件**再抄写，并标注真实文件路径与行号。宁可不贴代码，也不许编。

## 五、写作质量要求

1. **中文、直接、不客套。** 不要"让我们一起来学习"这类填充句。
2. **重点用加粗或徽章标记**，但不要通篇加粗。
3. **比喻要具体、贴生活**。反例："像缓存一样"；正例："像把经常用的工具放在手边抽屉，而不是每次都去仓库拿"。
4. **每个技术点写完自检三问**：
   - 为什么需要它？（不说会怎样）
   - 为什么用这个方案而不是另一个？（对比过什么）
   - 面试官会怎么追问？（预判 1~2 层）
5. **诚实标注边界**。项目没做的（V5、真流式、沙箱支付、ES 搜索）要明确写"未实现/简化"，这对面试是**加分**（化被动为主动）。
6. **不要重复其他页面的内容**——跨页主题只在该页讲透，其他页一句话带过并注明"详见 05 页"。
