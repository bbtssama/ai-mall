AI 种草商城 · 开发手册

这份手册只解决一件事：让你在最短时间内把 ai-mall 这个项目从"知道名字"变成"能讲清楚、扛得住追问"。 它不讲泛泛的八股，只讲这个项目里真实存在的代码、真实的取舍、真实的口径。

4 个版本域 · 191 个 Java 文件 24 张表 · 14 个 Controller 单体为主 · 只拆了 AI 服务 V1~V4 已落地 · V5 未开始

1先用 30 秒搞清楚：这是个什么项目

一句话定位：一个"内容社区为流量入口、电商交易为变现主干、AI 为智能引擎"的商城。

它由三块拼成，缺一块都不成立：

内容社区

用户可以发"种草笔记"（图文 + 关联商品），刷 Feed 流，点赞收藏。
为什么要它：没有内容，商城就只是个普通 CRUD——内容社区带来"用户生成内容"这个真实的高并发、非结构化场景。

笔记 / Feed 游标分页 / 点赞幂等 / 全文检索

电商交易

浏览商品 → 加购物车 → 下单 → 支付 → 收货。
为什么要它：这是资损场景的集中地——超卖、重复支付、订单超时，每一个都能问出真东西。

防超卖 / 幂等 / 支付闭环 / 限量发售

AI 导购

AI 客服问答，能调工具查商品（Function Calling），也能基于说明书和笔记回答"用起来怎么样"。
为什么要它：给上面两块提供"AI 时代"的业务合理性，也让技术叙事有落点。

Function Calling / RAG / 多模态识图
两条你必须先记住的"叙述纪律" 第一，AI 是了解层。开口先讲秒杀、支付、补偿、缓存，AI 只说"业务场景之一"。这决定了你在这份手册上的时间分配——06 页 AI 模块只需要 15 分钟。
第二，每个技术决策都要能答"砍掉它会怎样"。这个项目的设计原则是"业务驱动演进、绝不塞技术"。所以手册里每个点都会写明"为什么需要它"。

3全局架构：一张图看完谁调用谁

先看这张图。后面所有页面的内容，都是这张图上某个方框的展开。

浏览器 · Vue 3 + Vite（5173）
12 个页面组件（商品/购物车/订单/笔记/聊天/模拟收银台）· Pinia 状态 · axios 拦截器带 Token · SSE 流式渲染 AI 回复
↓ 所有请求统一走 /api/**（Vite 代理 → 网关 9000）
网关 · gateway（9000）
4 条路由：mall_apimall_filesmall_actuatordeny_internal
职责：路由转发 + TraceIdGlobalFilter 注入链路 ID + 把 /internal/** 全部拒掉（404）
↓ lb://mall-app（Nacos 服务发现）
mall-app · 主单体（8080）
6 个业务域：user / goods / content / order / pay / voice
基础设施：R / BusinessException 全局异常 / 分页 / traceId / Redis 门面 / 存储抽象 / 补偿任务
ai-service（8081）
ChatClient 装配 · RAG 语料与检索 · searchProduct / searchDocs 两个工具
注意：网关没有它的路由，内部走 HMAC 直连
↓ mall-app ⇄ ai-service 走 HTTP + @HttpExchange 声明式客户端 + HMAC 签名鉴权（带熔断降级）
MySQL 8
24 张表 · Flyway 管版本 · 行锁 CAS 扣库存
Redis
缓存三兄弟 / 计数增量桶 / 热榜 zset / 限流 Lua / 分布式锁
RabbitMQ
3 组交换机：审核异步 / 订单延迟取消 / 限量发售削峰
对象存储
本地磁盘（默认，零依赖）⇄ MinIO，配置一行切换
看这张图要抓的 3 个"设计意图" 1. 为什么只有一个网关而没有一堆微服务？因为主体是单体，网关在这里主要兑现"统一入口 + 链路 ID 注入 + 内部接口隔离"三件事，不是为了微服务而微服务。
2. 为什么 ai-service 不走网关？它是服务间调用不是外部入口，走网关反而绕远；且它的接口路径是 /internal/v1/**，网关明确拒掉，避免被外部直接打到。
3. 为什么三件中间件都可"降级"？Redis 挂了走 DB、MQ 挂了走线程池——这是项目"零依赖能启动"的硬约束，也是最好的面试素材。

5版本演进：这个项目是怎么长出来的

面试时"介绍一下你的项目"最忌讳平铺。"按版本演进讲"能体现你有迭代思维，也让面试官知道每加一层都有理由。

V1 · 单体电商闭环 已完成
注册登录 → 商品 → 购物车 → 下单（防超卖）→ 订单，外加 AI 问答（工具调用 + 识图 + SSE）。这是"能把功能跑通"的最小闭环。
Sa-Token · MyBatis 手写 SQL · 行锁 CAS 扣库存 · Spring AI
V1.5 · 工程基建 已完成
从"能跑"到"能上线"：数据库版本化、日志能串起来、文件能存、异步不炸、有测试有 CI。这一层不产功能，产可信度。
Flyway · traceId 三件套 · 对象存储抽象 · 有界线程池 · 26 个单测 · CI
V2 · 内容社区 + Hybrid RAG 已完成
补上"内容"这块地基：发笔记、刷 Feed、点赞收藏；AI 审核走 MQ 异步；RAG 把说明书和笔记变成可检索语料。
游标分页（二元组）· ngram 全文检索 · 点赞唯一索引幂等 · RRF 融合
V3 · 支付 + Redis + 高并发治理 已完成
项目的"含金量担当"：真收钱（支付闭环）、真扛量（限量发售削峰）、真治理（缓存/限流/延迟消息/补偿）。
Redis 预减 + MQ 异步下单 · TTL+DLX 延迟取消 · HMAC 验签 · 幂等三层 · 补偿任务
V4 · 服务化（只拆 AI） 已完成
按"耗时差异 + 故障隔离 + 独立扩容 + 密钥隔离 + 模型可替换"五条理由，只把 AI 拆出去，主体仍是单体。这个"克制"本身就是论点。
@HttpExchange · HMAC 内部鉴权 · Resilience4j 熔断 · Nacos · Gateway
V5 · 可选加分 未开始
Agent 客服查订单、相似推荐 + ItemCF 离线对比、受限 NL2SQL 商家看板。面试一律说"规划中"，不要含糊其辞。
