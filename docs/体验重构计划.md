# AI 种草商城 V1 体验重构计划

> 范围：在不脱离 V1 架构（单体、现有后端接口/数据模型基本不动）的前提下，对前端做一次
> 面向"主流电商体验"的大规模重构，补齐【我的】等基础功能。
> 目标：视觉上像样的商城前端；信息架构完整（首页/分类/详情/购物车/订单/我的/AI）。

---

## 一、现状问题审计

### 1. 前端表现问题（逐页）

**全局（App.vue）**
- 头部过于简陋：仅"logo 文字 + 一排 text 按钮 + 用户下拉"，无品牌图形、无搜索框、无购物车角标。
- 无页脚；整体缺少统一视觉语言（主色/强调色/圆角/阴影/间距散落定义，未收敛成设计 token）。
- `el-main` 无内容最大宽度约束，大屏下内容铺满、行宽过长。

**首页（Home）**
- banner 是简单线性渐变 + 一句话，商品位与"种草"气质弱。
- 商品卡片无层级：无卡片阴影、无销量/评分等社交信息，信息密度低。
- 无分区结构（如"为你推荐 / 数码 / 美妆"）、无分类导航条。
- 分页器小巧，无"上一屏/加载更多"体验。

**商品详情（ProductDetail）**
- 右侧信息"块太长"：规格、数量、三个按钮纵向堆叠成一长条；规格用 tag 平铺不直观。
- 图片区仅一张主图，无缩略图联动，无参数区，底部"商品详情"是一整段纯文本（很长）。
- "加入购物车"后无角标/动效反馈。

**购物车（Cart）**
- 表格整体"块感重"：行高较大、商品列 + 数量/库存列纵向堆叠，观感笨重。
- 结算弹窗偏窄（560px），地址卡片 + 新增表单纵向排布很长。
- 无地址编辑入口（只能新增）；无失效项分组；合计未"吸底"。
- 无空购物车插画/引导（有 basic el-empty）。

**订单（Orders）**
- 每张订单卡片都是"订单号→金额→收货"的纵向长块，列表一长串无重点。
- 无状态筛选 tab（全部/待支付/已支付/已完成/已取消），找单靠翻。
- 明细弹窗朴素。

**聊天（Chat）**：基本可用，可轻量优化（会话列表/气泡间距/输入区）。

### 2. 基础功能缺失

1. **没有【我的】页面**：用户资料、收货地址、订单入口、退出登录 没有聚合入口（当前只有 header 下拉能退出）。
2. **地址无统一管理**：现在只能在结算弹窗"新增"，无法编辑/删除/设默认管理（后端 `/api/v1/addresses` 已具备 update/delete/设默认，前端未接管理页）。
3. **导航信息架构弱**：首页无分类入口、无搜索、购物车无角标、无"我的"。
4. 详情页无规格图联动 / 参数表；订单无状态筛选。

---

## 二、重构目标与原则

- **不脱离 V1**：单体架构、现有后端接口、数据表基本不动；仅前端重构 + 复用现有接口。
- **参考主流电商**（京东/天猫/拼多多）：白底卡片 + 强调色 + 阴影层级 + 紧凑信息密度。
- **统一设计语言**：CSS 设计 token（主色 / 状态色 / 圆角 / 阴影 / 间距 / 内容最大宽度）。
- **组件化**：商品卡片、商品行、订单卡等抽成复用组件，避免每个页面散写样式。

---

## 三、实施计划（分阶段，逐步可交付）

### 阶段 A：设计基座 + 信息架构（App 骨架重构）
- A1 `assets/tokens.css`：主色（如活力橙红 #ff5000 系）、成功/警告/危险、圆角、阴影、间距、内容宽度 1200px 等 token。
- A2 `App.vue` 重构：新 Header = logo + 搜索框（轻量：关键词/分类过滤）+ 主导航（首页/分类/购物车(角标)/订单/AI助手）+ 用户区（【我的】入口 + 下拉含退出/地址）；新 Footer；`el-main` 限宽居中。
- A3 路由新增 `/mine`（我的）、`/mine/addresses`（地址管理）、`/category/:id`（分类列表，轻量）。

### 阶段 B：核心页面重构
- B1 首页 `Home`：分类导航条 + banner（可轮播静态图）+ 分区块（为你推荐/数码/美妆/食品…）+ 商品卡片组件化（图/卖点/起价/销量），翻页/加载。
- B2 商品详情 `ProductDetail`：主图 + 缩略图、价格/卖点强调区、SKU 规格卡片选择（选中态）、数量+加购/立即购买紧凑排布、参数小表、底部详情折叠、加购角标反馈。
- B3 购物车 `Cart`：紧凑化自定义行（图+信息一行、数量/库存横向、失效分组下沉）、合计吸底栏、结算弹窗加宽 + 地址选择更紧凑（卡片单行）。
- B4 订单 `Orders`：顶部状态筛选 tab（全部/待支付/已支付/已完成/已取消，前端过滤即可）+ 订单卡片紧凑化（商品缩略图 + 状态 + 合计）+ 明细 Drawer。
- B5 聊天 `Chat`：间距/气泡/发送条轻量优化（低优先）。

### 阶段 C：基础功能补全
- C1 【我的】`/mine`：个人信息卡（头像/昵称/登录态）+ 功能入口列表（我的订单 / 收货地址 / AI 助手 / 退出登录）。
- C2 收货地址管理 `/mine/addresses`：地址列表（默认徽标）、新增、编辑、删除、设默认 —— 对接现有 `/api/v1/addresses`（POST/PUT/DELETE/PUT default）。
- C3 结算弹窗地址区：改为"选择已存地址 + 链接去管理"，新增仍可弹内完成。

### 阶段 D：细节打磨 + 验证 + 提交
- 空态 / 加载 / 错误态统一；toast；轻微动效。
- 浏览器全链路回归：登录 → 首页浏览 → 分类 → 详情 → 加购 → 购物车勾选结算（含地址选择/新增）→ 下单 → 我的-订单-状态筛选 → 地址管理 → AI 对话。
- git 分阶段提交（每个阶段一个 commit）。

## 四、验收标准（V1 体验不糙）

| 维度 | 验收 |
|---|---|
| 视觉 | 主页/详情/购物车/订单 = 现代电商观感，无"大白块、长条堆叠" |
| 信息架构 | Header 有搜索/分类/购物车角标/【我的】；有 Footer |
| 功能补全 | 【我的】+ 地址管理（增/改/删/默认）可用；订单状态筛选可用；详情规格选择直观 |
| 回归 | V1 核心闭环全部走通（AI 问答、下单、地址与库存校验不回归） |
| 架构 | 未引入新后端表/新服务；后端仅按需补充极小的查询参数（如分类过滤） |
